# How To: Set Up Kafka CDC Streaming

Use change data capture (CDC) to observe a synthetic academic subject
descriptor's creation, update, and deletion in Kafka UI. This evaluation uses
the self-contained identity provider and Data Standard 5.2. The API also
supports 6.1. See
[Event Streaming with Kafka](../platform-dev-guide/features/event-streaming-kafka-cdc.md)
for the message contract and consumer responsibilities.

:::important Use a fresh, isolated environment

This evaluation runs one broker and one Kafka Connect worker with Kafka
authorization disabled. Use synthetic data only. It requires a new Configuration
Service database and a new API data store. Adding the flags below to an existing
deployment is not a supported way to enable streaming.

Use one database tab throughout. Run the two alternatives separately: they share
container names, ports, the `dms-local` Compose project, and the `dms` Docker
network. No unrelated containers may share this network. Keep other API
processes, IDE hosts, and seed loaders stopped until bootstrap finishes.

Successful message delivery demonstrates this evaluation. It does not establish
aggregate readiness: the standalone status command can report unknown
cache-refresh health. [Check Status](#check-status) explains how to distinguish
that result from other failures.

:::

## Prepare the Host

Use a Linux host with these tools available to the same user:

- PowerShell 7.5 or later (`pwsh`). The scripts check Linux file ownership.
- Docker Engine and the Docker Compose plugin, supporting Compose v2 syntax
  including `!override`. The user must be able to run `docker ps`.
- The .NET 10 SDK, Git, and internet access to the image registries and Ed-Fi
  package feed. Bootstrap builds its matching command-line tools from source.

Reserve loopback ports `8080` (Ed-Fi API), `8081` (Configuration Service),
`8083` (Kafka Connect), `8088` (Kafka UI), `9092` (broker), and `9404` (worker
metrics). Also reserve `5435` for PostgreSQL or `1435` for SQL Server.

Clone the release and enter PowerShell. Run all subsequent commands from the
repository root in the same PowerShell session, unless a step says otherwise.
Expand and run each setup block in order.

```bash
git clone --depth 1 --branch v8.1.0 https://github.com/Ed-Fi-Alliance-OSS/Data-Management-Service.git
cd Data-Management-Service
pwsh
```

The source tag fixes the scripts, schema package versions, and database/Kafka
image references. Kafka Connect uses the qualified image
`edfialliance/ed-fi-kafka-connect@sha256:bfabcabfd28868d32ab0271b42b7d147b9566c89bfe1747716368208e8291921`.
Do not substitute a floating image tag. SQL Server uses the release's
`mcr.microsoft.com/mssql/server:2025-latest` reference; record its resolved
image identity when retaining evaluation results.

## Prepare Private Configuration

The environment and settings files contain credentials. Keep them out of source
control, shared transcripts, and screenshots. These commands refuse to replace
an existing environment file, protect the directories, and assign unique local
image names so another checkout's cached application images are not reused.

## Start the Database and Configuration Service

This preparation starts infrastructure only. It does not create the new
`edfi_cdc` data store or start API writers. The first run builds the
Configuration Service image and can take several minutes.

```powershell
pwsh ./eng/docker-compose/start-local-dms.ps1 -InfraOnly -EnableConfig `
    -SeparateConfigDatabase -CdcDatabaseInfrastructure -DatabaseEngine $databaseEngine `
    -IdentityProvider self-contained -EnvironmentFile $environmentFile
if ($LASTEXITCODE -ne 0) { throw 'Infrastructure failed; keep API writers stopped.' }
```

The Configuration Service uses its own `edfi_configurationservice` database. The
new `edfi_cdc` database must not already exist. Ignore the generic manual IDE
next-steps printed by infrastructure preparation; continue below with the CDC
bootstrap instead of registering or provisioning a data store separately.

### Prepare the Connector Login

The connector reads captured data using a restricted account. The setup
administrator is a separate account used by bootstrap to prepare the database.
Do not grant the connector administrator access or resource-table writes.

replication slot, and progress table. Do not create these yourself.

</TabItem>

In this fresh Configuration Service, the first data-store registration has ID
`1`. Both DocumentCache and CDC must select that same ID. Bootstrap checks the
ID returned by registration before provisioning. This expectation is valid only
when the Configuration Service has had no prior data-store inserts, including
deleted registrations, and no concurrent configuration activity. Do not run
registration separately to discover an ID; doing so would consume it.

Load the complete API settings and fill in this environment's Configuration
Service credentials. The API keeps read acceleration disabled while the cache
refresh process supplies streaming.

## Start the API and Streaming

Bootstrap stages the Data Standard packages, registers the first data store,
creates and provisions `edfi_cdc`, and coordinates cache activation and CDC. It
starts the API only after the managed initial checks succeed. No separate cache
activation or seed loading is required for the descriptor example.

```powershell
pwsh ./eng/docker-compose/bootstrap-local-dms.ps1 -DatabaseEngine $databaseEngine `
    -EnableKafkaCdc -SeparateConfigDatabase -DataStoreDatabaseName edfi_cdc `
    -CdcSettingsPath $settingsPath -CdcBindingStatePath $statePath `
    -EnvironmentFile $environmentFile -DataStandardVersion '5.2' `
    -IdentityProvider self-contained -EnableKafkaUI -AddSmokeTestCredentials
if ($LASTEXITCODE -ne 0) { throw 'Bootstrap failed; retain state and keep other writers stopped.' }
```

Expect successful completion, the API discovery address, test client
credentials, and an `Inspect CDC` command. Save the credentials privately. Copy
the **exact** settings and state paths printed in `Inspect CDC`; the settings
path is a new file under `eng/docker-compose/.bootstrap/cdc-runtime`. Do not
select the newest file by timestamp or reuse the input settings file.

Keep `.env`, any `.derived` environment files, the entire `.bootstrap`
directory, `eng/docker-compose/.cdc-deployments`, and the original state
directory together. They contain the information needed to safely stop and
resume the environment. Moving or deleting them is not a supported reset.

## Check Status

Resolve the same SchemaTools executable used by bootstrap, then enter the paths
from its printed `Inspect CDC` command:

```powershell
Import-Module ./eng/docker-compose/bootstrap-schema-tool.psm1
$schemaTool = Resolve-DmsSchemaTool
$retainedSettings = Read-Host 'Exact settings path from Inspect CDC'
$retainedState = Read-Host 'Exact state path from Inspect CDC'
& $schemaTool cdc status --settings $retainedSettings --state-path $retainedState --json
$statusExitCode = $LASTEXITCODE
```

Status can record incidents and stop connectors. Keep the JSON on standard
output and diagnostics on standard error private. Exit `0` with
`data.aggregate.readiness: "Ready"` confirms readiness at the time of the check.
On exit `1` with projection `Unknown`, an explicit `RuntimeNotObserved` means
the CLI could not observe the API's cache-refresh process. If the only reason
given is `StatusObservationUnavailable` or Projection / `Unavailable`, the cause
is unknown. Check other components and verify message delivery separately.

Bootstrap authorizes API startup. The local profile reports
`deploymentProfile.aclIsolationProven: false` because Kafka authorization is
disabled. For a component failure or timeout, [troubleshoot](#troubleshooting)
before the next write. For invalid input, cancellation, or an incident, see the
[full exit-code table and incident results](../platform-dev-guide/utilities/database-provisioning.md#check-cdc-status).

## Create and Observe a Resource

The bootstrap's test credentials belong to the `EdFiSandbox` claim set and are
for this disposable environment only. Enter the printed key and secret without
placing them in command arguments, then request a token:

```powershell
$clientId = Read-Host 'Bootstrap test client key'
$clientSecret = Read-Host 'Bootstrap test client secret' -MaskInput
$token = Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/api/oauth/token' `
    -ContentType 'application/x-www-form-urlencoded' -Body @{
        grant_type = 'client_credentials'; client_id = $clientId; client_secret = $clientSecret
    }
$headers = @{ Authorization = "Bearer $($token.access_token)" }
$resourceUrl = 'http://localhost:8080/api/data/ed-fi/academicSubjectDescriptors'
$body = @{
    namespace = 'uri://ed-fi.org/AcademicSubjectDescriptor'
    codeValue = 'CdcDemo'; shortDescription = 'CDC demonstration'
    description = 'Synthetic data for a local streaming evaluation'
}
$response = Invoke-WebRequest -Method Post -Uri $resourceUrl -Headers $headers `
    -ContentType 'application/json' -Body ($body | ConvertTo-Json)
$response.StatusCode
$documentId = ([string]$response.Headers.Location[0]).TrimEnd('/').Split('/')[-1]
$documentId
```

Expect HTTP `201` and a UUID. The descriptor has no prerequisite resources.

Open `http://localhost:8088` in your browser. Select cluster **kafka1**, open
**Topics**, and select `edfi.instance.datastore-1-g1.documents.v1`. Open
**Messages**, keep **Oldest First**, and click **Submit** to read from the
beginning. Expand a message row to inspect its value. Inspect the record whose
key matches `$documentId`; refresh/poll for up to **120 seconds**.

Before continuing, verify:

- The key is the lowercase UUID, matching `documentUuid` and `document.id`.
- The value is a JSON envelope with `contractVersion: 1`,
  `projectName: "Ed-Fi"`, `resourceName: "AcademicSubjectDescriptor"`, and
  `resourceVersion: "5.2.0"`.
- `document.shortDescription` is `CDC demonstration`.
- Record the `contentVersion` and `documentCreatedAt` for comparison.

If the record is absent after 120 seconds, stop here and use
[Troubleshooting](#troubleshooting). Do not update and delete rapidly: cache
refresh can combine intermediate changes before publication.

## Update and Observe a Higher Version

```powershell
$body.id = $documentId
$body.shortDescription = 'CDC demonstration updated'
$response = Invoke-WebRequest -Method Put -Uri "$resourceUrl/$documentId" `
    -Headers $headers -ContentType 'application/json' -Body ($body | ConvertTo-Json)
$response.StatusCode
```

Expect HTTP `204`. In Kafka UI, refresh/poll for up to **120 seconds** for a
message with the same key, the updated description, and a **higher**
`contentVersion`. Its `documentCreatedAt` must remain unchanged. Observe this
message before deleting. Earlier messages may disappear through compaction; the
topic is a stream of resource state, not a permanent change history.

## Delete and Observe the Tombstone

```powershell
$response = Invoke-WebRequest -Method Delete -Uri "$resourceUrl/$documentId" -Headers $headers
$response.StatusCode
```

Expect HTTP `204`. Refresh/poll Kafka UI for up to **120 seconds** for the same
key with a **null message value**. This tombstone has no JSON envelope or
`contentVersion`. If the UI has a value filter, remove it so null values are
visible. Stop and investigate if the expected record does not arrive.

## Stop and Resume the Evaluation

Keep the checkout and all its private state. With no external API or seed
processes running, use the same bootstrap wrapper to stop the retained stack:

```powershell
pwsh ./eng/docker-compose/bootstrap-local-dms.ps1 -d -EnableKafkaUI
if ($LASTEXITCODE -ne 0) { throw 'Managed stop failed; retain all state.' }
```

The wrapper reads its saved deployment inventory, stops connectors and verifies
that their tasks stopped, then stops the infrastructure while retaining data. To
resume from a successful stop:

```powershell
pwsh ./eng/docker-compose/bootstrap-local-dms.ps1 -EnableKafkaUI
if ($LASTEXITCODE -ne 0) { throw 'Managed start failed; keep external writers stopped.' }
```

Repeat `-EnableKafkaUI` so the optional UI is included in both operations. The
wrapper restores the original database engine and settings, validates source and
connector history, and starts the API after the managed checks pass. Do not
repeat initial enablement flags or register another data store.

Request a fresh API token and create another synthetic descriptor:

```powershell
$token = Invoke-RestMethod -Method Post -Uri 'http://localhost:8080/api/oauth/token' `
    -ContentType 'application/x-www-form-urlencoded' -Body @{
        grant_type = 'client_credentials'; client_id = $clientId; client_secret = $clientSecret
    }
$headers = @{ Authorization = "Bearer $($token.access_token)" }
$body.Remove('id')
$body.codeValue = 'CdcDemoAfterRestart'
$response = Invoke-WebRequest -Method Post -Uri $resourceUrl -Headers $headers `
    -ContentType 'application/json' -Body ($body | ConvertTo-Json)
$response.StatusCode
$documentId = ([string]$response.Headers.Location[0]).TrimEnd('/').Split('/')[-1]
$documentId
```

Expect HTTP `201`. Confirm the new key's envelope appears within 120 seconds on
the **same topic generation**. This checks resumed delivery as well as
successful command exits.

Ordinary stop preserves all data. Destructive retirement and volume deletion are
outside this walkthrough; deleting only some volumes or state files can make the
remaining environment unusable. The optional
[advanced operations reference](https://github.com/Ed-Fi-Alliance-OSS/Data-Management-Service/blob/v8.1.0/reference/cdc-documentation/operations-runbook.md#stack-teardown)
covers coordinated retirement and cleanup.

## Troubleshooting

Use bounded, read-only checks before deciding what to do next:

```powershell
docker ps --filter label=com.docker.compose.project=dms-local
Invoke-RestMethod http://localhost:8080/api/health
Invoke-RestMethod http://localhost:8081/config/health
$connectors = Invoke-RestMethod http://localhost:8083/connectors
foreach ($name in $connectors) {
    Invoke-RestMethod "http://localhost:8083/connectors/$name/status" | ConvertTo-Json -Depth 10
}
```

A running connector and task are expected. For private diagnostics, inspect
recent service logs; they may contain sensitive information:

```powershell
docker logs --tail 100 ed-fi-api
docker logs --tail 100 dms-local-kafka-cdc-worker-1
```

| Symptom                                        | Likely cause and next action                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Infrastructure fails before registration       | Check free ports, Docker access, image/package download errors, and the selected engine. Keep API writers stopped. Correct the prerequisite and repeat the same infrastructure command.                                                                                                                                           |
| Data-store ID mismatch                         | Configuration Service was not fresh or another registration occurred. Preserve the registration and settings. Do not register again, reset an identity counter, or guess another ID. Stop this walkthrough and resolve the environment selection.                                                                                 |
| Bootstrap fails after provisioning begins      | Preserve the original settings, `.bootstrap`, deployment inventory, and state root. Read the reported stage and diagnostic code. Do not delete state or provision again. An interrupted initial operation may be retried only with its retained workflow and unchanged inputs; obtain operator support if its stage is uncertain. |
| API request returns `401` or `403`             | Request a new token with the bootstrap's test credentials. Confirm the exact resource namespace and data-store assignment; an HTTP health response does not validate client access.                                                                                                                                               |
| No public message after 120 seconds            | Confirm the API request succeeded and the correct topic/key is selected. Check the connector and task status, then run `cdc status` with the emitted paths. Inspect recent API/worker logs privately. Fix the reported failure before advancing to the next operation.                                                            |
| `RuntimeNotObserved` with projection `Unknown` | This is the standalone observation limitation described above. Record it accurately and separately check delivery. It does not excuse failed connector tasks, missing capture progress, or failed bootstrap.                                                                                                                      |
| Connector task failed                          | Inspect its status and private worker logs for the specific error: credentials, unavailable source history, malformed resource, or record-size rejection. Do not set error tolerance to skip records or reset offsets. Preserve evidence and use the supported recovery procedure for that failure.                               |
| SQL Server prerequisites or capture jobs fail  | Use the database checks above and confirm Agent is running. Keep writers stopped on failed initial setup. Changing prerequisites after activation or recreating capture history is not a supported repair.                                                                                                                        |
| Stop/start fails or reports missing state      | Keep all retained files and volumes. Inspect diagnostics and keep external writers stopped. Do not use volume deletion or raw Connect restart/resume requests to bypass the managed checks.                                                                                                                                       |

For advanced failures beyond this local recipe, consult the optional
[operations reference](https://github.com/Ed-Fi-Alliance-OSS/Data-Management-Service/blob/v8.1.0/reference/cdc-documentation/operations-runbook.md#procedure-navigation).
