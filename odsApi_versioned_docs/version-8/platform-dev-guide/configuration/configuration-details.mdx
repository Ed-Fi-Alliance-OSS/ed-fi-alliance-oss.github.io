# Configuration Details

Ed-Fi API v8 is configurable through `appsettings.json` in each service. This
page documents the most common settings. Environment variables override
`appsettings.json` values using the double-underscore `__` separator for
hierarchy — for example, `AppSettings__Datastore=mssql`. No special prefix is
required.

## Ed-Fi API Settings

### Required Settings

The Ed-Fi API requires a reachable Configuration Service, the shared connection
string encryption key, and JWT authentication settings to start. In the Docker
Compose setup these are provided via the `.env` file; in other deployments
configure them directly in `appsettings.json` or via environment variables. The
[`JwtAuthentication`](#jwtauthentication) section points the Ed-Fi API at the
token authority — see also [Identity Provider](./identity-provider.md).

- **`AppSettings:Datastore`**

  |             |                                                                                |
  | ----------- | ------------------------------------------------------------------------------ |
  | Example     | `postgresql`                                                                   |
  | Description | Primary database engine for the Ed-Fi API. Valid values: `postgresql`, `mssql` |

- **`ConfigurationServiceSettings:BaseUrl`**

  |             |                                                                                                                                                |
  | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
  | Example     | `http://ed-fi-api-config:8081`                                                                                                                 |
  | Description | Base URL of the Configuration Service. The Ed-Fi API contacts this URL at runtime to retrieve claim sets, data stores, and application context |

- **`ConfigurationServiceSettings:EncryptionKey`**

  |             |                                                                                                                                                                                                                                                                                                                                                                                        |
  | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Example     | `MySecretKey1234567890123456789012`                                                                                                                                                                                                                                                                                                                                                    |
  | Description | Key used to decrypt data store connection strings stored in the Configuration Service. Required: while it is empty, the Ed-Fi API reports a configuration error and answers every request with HTTP 500 until it is corrected. Must match `DatabaseSettings:EncryptionKey` in the Configuration Service. Docker Compose sets both from `CONFIGURATION_SERVICE_DATABASE_ENCRYPTION_KEY` |

- **`AppSettings:AuthenticationService`**

  |             |                                                                                                                                                                                       |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Example     | `http://ed-fi-api-config:8081/connect/token`                                                                                                                                          |
  | Description | Token endpoint the Ed-Fi API forwards `/oauth/token` proxy requests to. Must use the container-network hostname in Docker deployments. Docker Compose env var: `OAUTH_TOKEN_ENDPOINT` |

- **`ConfigurationServiceSettings:ClientSecret`**

  |             |                                                                                                                                                                                                                                           |
  | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Example     | _(generated secret)_                                                                                                                                                                                                                      |
  | Description | Client secret the Ed-Fi API uses to authenticate to the Configuration Service as the client named in `ClientId`. Must match the secret configured in the Configuration Service. Set via `DMS_CONFIGURATION_SERVICE_CLIENT_SECRET` env var |

  | Description | When `true`, enables multi-tenancy mode. The tenant identifier is extracted from the URL route. See [Single and Multi-Tenant Configuration](./single-and-multi-tenant-configuration.md) |

- **`AppSettings:RouteQualifierSegments`**

  |             |                                                                                                                                                                                                                                                                                                                   |
  | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

  | Description | Comma-separated list of route qualifier segments extracted from the URL path. Example: `districtId,schoolYear`. Segments must match `dataStoreContexts` configured in the Configuration Service. See [Context-Based Routing for Year-Specific Data Store](./context-based-routing-for-year-specific-datastore.md) |

- **`AppSettings:BypassTypeCoercion`**

  |             |                                                                                                                                                                                                                        |
  | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `false`                                                                                                                                                                                                                |
  | Description | When `true`, disables automatic type coercion on `POST` and `PUT` request values. Submitted values must already match the JSON Schema type. Improves performance but requires clients to submit correctly typed values |

- **`AppSettings:AllowIdentityUpdateOverrides`**

  |             |                                                                                                                                                  |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
  | Default     | _(empty)_                                                                                                                                        |
  | Description | Comma-separated list of resource names that allow natural key (identity) updates. By default all resources reject identity updates with HTTP 400 |

- **`AppSettings:MaskRequestBodyInLogs`**

  |             |                                                                                                                                                                                                                            |
  | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `true`                                                                                                                                                                                                                     |
  | Description | When `true`, masks request body content in `DEBUG`-level log statements by replacing all scalar values with `"*"`. When `false`, the full unmasked body is logged. See [Logging Configuration](./logging-configuration.md) |

- **`AppSettings:CorrelationIdHeader`**

  |             |                                                                                                                                                                                                                       |
  | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | _(empty)_                                                                                                                                                                                                             |
  | Description | Name of the request header a client-supplied correlation ID is read from. When empty, no header is read and the request's trace identifier is used. See [Correlation IDs](./logging-configuration.md#correlation-ids) |

- **`AppSettings:CorrelationIdMaxLength`**

  |             |                                                                                                                                   |
  | ----------- | --------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `255`                                                                                                                             |
  | Description | Maximum length of a correlation ID used in logs and error responses; longer values are truncated. Must be between `64` and `1024` |

- **`AppSettings:MaximumPageSize`**

  |             |                                                                                                                                                                                                          |
  | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `500`                                                                                                                                                                                                    |
  | Description | Upper bound for the `limit` and `pageSize` query parameters on GET-many requests, and the page size used when neither is supplied. Must be greater than `0`. Docker Compose env var: `MAXIMUM_PAGE_SIZE` |

- **`AppSettings:DefaultPartitionCount`**

  |             |                                                                                                                                                                                                                                                                                                                   |
  | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `10`                                                                                                                                                                                                                                                                                                              |
  | Description | Number of partitions a `/partitions` request returns when it omits the `number` query parameter. Must be between `1` and `200`. See [Improve Paging Performance with Cursor Paging](../../client-developers-guide/improve-paging-performance-cursor-paging.md). Docker Compose env var: `DEFAULT_PARTITION_COUNT` |

- **`AppSettings:UseLegacyDocumentIdOrderingForChangeQueries`**

  |             |                                                                                                                                                                                                                                    |
  | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `false`                                                                                                                                                                                                                            |
  | Description | When `true`, pages every request in creation order, including change queries that would otherwise be paged in change-version order. Leave it `false`. Docker Compose env var: `USE_LEGACY_DOCUMENT_ID_ORDERING_FOR_CHANGE_QUERIES` |

  By default, the Ed-Fi API pages some change queries in change-version order,
  which is faster on large collections. These are requests that include
  `maxChangeVersion`, and change-version-filtered requests served from a
  [snapshot](../features/changed-record-queries.md#changed-record-queries-with-snapshot-isolation).
  All other requests, including live requests with only `minChangeVersion`, are
  paged in creation order. When this setting is `true`, every request is paged
  in the order records were created, as in the ODS/API, and change queries on
  large collections are slower. Turn it on only if change-version ordering
  causes a problem, and turn it off again once the problem is fixed.

  Changing this setting, in either direction, invalidates page and partition
  tokens issued for requests that include `maxChangeVersion`, and for
  change-version-filtered requests served from a snapshot. Clients holding those
  tokens must start over, so make the change when no change queries are running.

- **`AppSettings:MaxRequestBodySizeMegabytes`**

  |             |                                                                                                       |
  | ----------- | ----------------------------------------------------------------------------------------------------- |
  | Default     | `10`                                                                                                  |
  | Description | Largest request body, in megabytes, the Ed-Fi API accepts. Larger requests are rejected with HTTP 413 |

Only schema files listed in the manifest are loaded. In the Ed-Fi API container, `SCHEMA_PACKAGES` can download the schema packages into this directory and write the manifest; see [Loading Schemas from Packages](../extensibility-customization/extending-api-datamodel.md#loading-schemas-from-packages) |

### DocumentCache

All settings below belong under `DataManagement:DocumentCache` in the API's
configuration. These v8.1.0 defaults leave projection idle and read acceleration
off. Database activation is a separate administrative step; see
[DocumentCache](../features/document-cache.md) and the
[administration CLI](../utilities/document-cache-admin-cli.md).

Restart API instances after changing these settings. Each CLI invocation loads
its configuration afresh. Durations use .NET `TimeSpan` syntax, such as
`00:00:00.250` for 250 milliseconds or `1.00:00:00` for one day.

| Setting below `DataManagement:DocumentCache` | Default          | Description and constraints                                                                                                                                             |
| -------------------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Targets`                                    | `[]`             | Explicit target list; empty means no runtime projection. Entries cannot be null or duplicate a normalized tenant/data-store pair.                                       |
| `Targets:<n>:TenantKey`                      | `""`             | Empty or null means the default tenant. Comparison is case-insensitive. No leading/trailing whitespace or control characters; must be safe as the `Tenant` HTTP header. |
| `Targets:<n>:DataStoreId`                    | No valid default | Required positive Configuration Service data store ID.                                                                                                                  |
| `ReadAcceleration:Enabled`                   | `false`          | Allows fresh cached bodies for eligible resource and descriptor GETs on configured targets.                                                                             |
| `ReadAcceleration:DirectFillTimeout`         | `00:00:00.250`   | Budget for optional best-effort direct fill after relational fallback. Positive, at most `4294967294` milliseconds.                                                     |
| `Projector:PollInterval`                     | `00:00:05`       | Positive polling interval.                                                                                                                                              |
| `Projector:PageSize`                         | `100`            | Positive number of items in a projector page.                                                                                                                           |
| `Projector:MaxConcurrentTargets`             | `2`              | Positive maximum number of targets projected concurrently by one process.                                                                                               |
| `Projector:FailureBackoff`                   | `00:00:30`       | Positive wait before retrying after a target-level failure.                                                                                                             |
| `Projector:BaselineHighWaterMark`            | `1000`           | Baseline projection high-water mark; integer from `1` through `2147483646`.                                                                                             |
| `Administration:WorkflowTimeout`             | `1.00:00:00`     | Positive total administrative workflow budget (24 hours).                                                                                                               |
| `Status:StatusObservationTimeout`            | `00:00:05`       | Per-target durable observation budget; positive, at most `4294967294` milliseconds.                                                                                     |
| `Status:EndpointTimeout`                     | `00:00:30`       | Overall HTTP status endpoint budget; positive, at most `4294967294` milliseconds.                                                                                       |
| `Status:RequiredRole`                        | Unset            | Single literal role needed to map and authorize `GET /health/document-cache`. Recommended: `dms-client`.                                                                |

Do not set `Targets`, `ReadAcceleration`, `Projector`, `Administration`, or
`Status` to null. `Status` may be omitted or an object (including `{}`), but
cannot be a scalar. Invalid configuration fails validation. An invalid
`Status:RequiredRole` instead leaves the status endpoint unmapped: the role must
be a single untrimmed token of at most 256 characters, without ASCII whitespace,
commas, semicolons, quotes, brackets, braces, or control characters. The
caller's role is read under `JwtAuthentication:RoleClaimType`.

Use these exact .NET environment variable names to override settings. Index `0`
is the first target; use `1`, `2`, and so on for additional entries.

```ini
DataManagement__DocumentCache__Targets__0__TenantKey=
DataManagement__DocumentCache__Targets__0__DataStoreId=1
DataManagement__DocumentCache__ReadAcceleration__Enabled=false
DataManagement__DocumentCache__ReadAcceleration__DirectFillTimeout=00:00:00.250
DataManagement__DocumentCache__Projector__PollInterval=00:00:05
DataManagement__DocumentCache__Projector__PageSize=100
DataManagement__DocumentCache__Projector__MaxConcurrentTargets=2
DataManagement__DocumentCache__Projector__FailureBackoff=00:00:30
DataManagement__DocumentCache__Projector__BaselineHighWaterMark=1000
DataManagement__DocumentCache__Administration__WorkflowTimeout=1.00:00:00
DataManagement__DocumentCache__Status__StatusObservationTimeout=00:00:05
DataManagement__DocumentCache__Status__EndpointTimeout=00:00:30
DataManagement__DocumentCache__Status__RequiredRole=dms-client
```

This example selects data store `1` and enables the protected status endpoint;
it does not activate the database or enable accelerated reads. The
`DMS_DOCUMENTCACHE_*` variables used by the
[optional Docker overlay](../../getting-started/getting-started-appendix.md#optional-documentcache)
are Compose conveniences, not configuration keys read directly by the API. Set
.NET variables in the container environment, not merely in the Compose `.env`
file unless an overlay maps them there.

### JwtAuthentication

These settings tell the Ed-Fi API how to validate the bearer tokens issued by
the identity provider. See [Identity Provider](./identity-provider.md) for
values for each provider.

- **`JwtAuthentication:Authority`**

  |             |                                                                                                                                                                          |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | Example     | `http://ed-fi-api-config:8081`                                                                                                                                           |
  | Description | Token issuer. Must exactly match the `issuer` in the identity provider's metadata document, or the Ed-Fi API does not start. Docker Compose env var: `DMS_JWT_AUTHORITY` |

- **`JwtAuthentication:MetadataAddress`**

  |             |                                                                                                                                                                        |
  | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Example     | `http://ed-fi-api-config:8081/.well-known/openid-configuration`                                                                                                        |
  | Description | OpenID Connect metadata endpoint. Signing keys are fetched only from this address's origin (scheme, host and port). Docker Compose env var: `DMS_JWT_METADATA_ADDRESS` |

- **`JwtAuthentication:Audience`**

  |             |                                                                                  |
  | ----------- | -------------------------------------------------------------------------------- |
  | Default     | `account`                                                                        |
  | Description | Expected audience of incoming tokens. Docker Compose env var: `DMS_JWT_AUDIENCE` |

- **`JwtAuthentication:RequireHttpsMetadata`**

  |             |                                                                                                                                                                                                                                                 |
  | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `true`                                                                                                                                                                                                                                          |
  | Description | Requires the metadata and signing-key documents to be fetched over HTTPS. Set to `false` only when the identity provider is reached over a private network; the Docker Compose files set it to `false` through `DMS_JWT_REQUIRE_HTTPS_METADATA` |

- **`JwtAuthentication:RoleClaimType`**

  |             |                                                                                                                                                                                      |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | Default     | `http://schemas.microsoft.com/ws/2008/06/identity/claims/role`                                                                                                                       |
  | Description | Claim type that carries role values in tokens. Used by endpoints that require a configured role, such as the management endpoints. Docker Compose env var: `DMS_JWT_ROLE_CLAIM_TYPE` |

- **`JwtAuthentication:ClientRole`**

  |             |                                                                                                                                                                                                                                                                                                                                                                                                                              |
  | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `service`                                                                                                                                                                                                                                                                                                                                                                                                                    |
  | Description | Role that every access token must carry. A token without it gets `403 Forbidden`. Set it to the role your identity provider gives API clients, such as `dms-client`, the self-contained default (`IdentitySettings:ClientRole`). Empty turns the check off. The following settings control how the Configuration Service keeps its token
signing keys in memory. They apply only in self-contained mode, aren't mapped in
the Docker Compose files, and are checked at startup: the Configuration Service
doesn't start when a value is out of range. See
[Configuration Service Signing Keys](../../technical-articles/caching-strategy.md#configuration-service-signing-keys).

- **`IdentitySettings:SigningKeyRefreshIntervalSeconds`**

  |             |                                                                                                                           |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `300`                                                                                                                     |
  | Description | Seconds between scheduled reloads of the signing keys. Each wait varies by up to 10 percent. Must be from `30` to `43200` |

- **`IdentitySettings:SigningKeyMaxStalenessSeconds`**

  |             |                                                                                                                                                                                                                                                                                                                                                         |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `3600`                                                                                                                                                                                                                                                                                                                                                  |
  | Description | Age, in seconds, at which the loaded signing keys are no longer trusted. Until a reload succeeds, requests that need a bearer token and the JWKS endpoint get `503`, and introspection reports every token as inactive. Issuing and revoking tokens aren't affected. Must be at least twice `SigningKeyRefreshIntervalSeconds` and no more than `86400` |

- **`IdentitySettings:SigningKeyUnknownKeyRefreshCooldownSeconds`**

  |             |                                                                                                                                 |
  | ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `30`                                                                                                                            |
  | Description | Minimum seconds between the end of a load and a reload caused by a token signed with an unknown key. Must be from `1` to `3600` |

- **`IdentitySettings:SigningKeyLoadTimeoutSeconds`**

  |             |                                                                                                                                                       |
  | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
  | Default     | `10`                                                                                                                                                  |
  | Description | Seconds after which a signing key load is cancelled and counted as failed. Must be from `1` to `60`, and less than `SigningKeyRefreshIntervalSeconds` |

`IdentitySettings:KeyFormatCacheSize` is no longer read. Remove it from your
configuration; it has no effect.
