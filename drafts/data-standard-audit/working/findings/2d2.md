# Findings 2d2: Data Standard v6 landing, navigation, and change-history pages

## Scope

- Page types: `ds-landing` (3 pages) and `whats-new` (6 pages) in Data Standard (DS) v6.
- Pages audited (all under `dataStandard_versioned_docs/version-6/`): `readme.md`, `handbook.md`, `model-reference/readme.md`, `whats-new/readme.md`, `whats-new/whats-new-v60.md`, `whats-new/whats-new-v61.md`, `whats-new/api-changes-6.md`, `whats-new/api-changes-61.md`, `whats-new/migration-guide.md`.
- Comparison only: `version-5/readme.md`, `version-5/whats-new/readme.md`.
- Navigation: the Data Standard sidebar is autogenerated from the folder tree (`dataStandard_versioned_sidebars/version-6-sidebars.json` is `{"type":"autogenerated","dirName":"."}`). Nothing in `sidebars.js` curates it. The sidebar therefore cannot carry any descriptive text, so the index pages must.
- Questions: the 48 `change-history` and `orientation` questions in `questions.yaml`.

## Method

- Read each page's source in full, plus the rubric, terminology guidelines, and `plan.md`.
- Checked `working/inventory-html.csv` (title, meta description, visible words), `working/version-diff.csv`, and `working/retrieval-results.csv`.
- Used `grep` for link and term counts. Checked the built HTML under `build/` for one link.
- Rated each question by what the audited pages themselves say. Where the answer lives on a domain page (out of scope), that is noted.
- Not done: the per-page score table (only required of Phase 2b/2c).

## Summary

- The v6 landing page is a near copy of the v5 landing page (`sim_v6_v5` = 0.843). It never defines the Ed-Fi Data Standard in plain terms and never links to the Model Reference. It also says nothing about domains, the four-page structure, school-year guidance, or the Ed-Fi ODS/API. It answers "which version" only as "v6.1 is current".
- The Model Reference index (182 words) lists no domains. The body is two note and link blocks. The 26 domains appear only in the autogenerated sidebar, so a retrieved passage has no domain map. It also labels the 6.0 Handbook "(Latest version)" beneath the 6.1 Handbook.
- The change history is strong on rationale for the 6.0 and 6.1 releases. It can answer "what changed in 6.0", "what's in 6.1", and "is 6.1 breaking". Of the 48 change-history and orientation questions, 23 are fully answerable from these pages. 10 are partial and 15 have no answer here.
- The change history lacks a per-change structure (breaking or non-breaking, who is affected, what to do) and an at-a-glance table. The word "breaking" appears 0 times in either API-changes page.
- The `whats-new` index lists only 3 of the 5 child pages. `api-changes-61.md` and `migration-guide.md` are not linked from it or from the v6 landing page. Domain pages almost never link back to What's New.
- The API-changes and migration pages are not self-contained. H1s such as "API Changes from 5.0 to 6.0" never say "Data Standard", so they collide with Ed-Fi ODS/API 5.0 and 6.0 numbering. In retrieval, `/reference/ed-fi-api/6.2/whats-new` outranks the DS pages for "what changed in data standard 6.0".
- The migration guide has copy-paste errors. They include a Staff section saying data was previously sent to the "StudentEducationOrganizationAssociation", a duplicated sentence naming StudentIdentificationCode, and a wrong anchor. It also omits breaking changes that What's New lists (`numericRating`, the descriptor namespace change, removed properties).
- The 6.0 and 6.1 pages disagree about FinancialAid. The 6.0 page and API-changes-6 file it under Enrollment, and the 6.0 page has no pointer to the 6.1 move.
- Terminology and typo problems are minor but real: "Ed-Fi Standards", "Unifying Modeling Language", "Ed Fi", "EdFi API", "deployment" of the Data Standard, plus stray typos in What's New v6.0.

## Recommended outlines

### v6 landing page (`readme.md`)

Front matter: `description:` of 120-160 characters (see 2d2-11). H1: "Ed-Fi Data Standard v6.1 Documentation".

1. Opening (no heading, 2-3 sentences). What the Ed-Fi Data Standard is: the common framework that keeps education data consistent, compatible and secure across systems. The Ed-Fi Unifying Data Model (UDM) is its data model. Name who uses it (SEAs, LEAs, SIS vendors, assessment vendors). State "This documentation covers Ed-Fi Data Standard v6.1 (v6.1.0, released May 7, 2026)." Keep the existing warning admonition.
2. Which version should I use? v6.1 (latest), v5.2 (still supported), links to supported versions, versioning and releases, and the v5 landing page. Add a school-year sentence sourced from `data-standards.md`. Mention that the Special Education Data Model in v6.1 is early access.
3. Is v6.1 a breaking change? A two-row table: 6.0 (breaking vs. 5.2), 6.1 (non-breaking vs. 6.0). Link to What's New and the Migration Guide.
4. How this documentation is organized. Domains (26, each a part of the model, for example Enrollment, Assessment, Staff), then the pages each has: Readme, Overview, Model Diagrams, Entities, References and Descriptors, and, in some domains, Best Practices and Use Cases. Link to the Model Reference index. Link to the UDM concepts pages and, when it exists, the concepts glossary.
5. How to read the model. Short definitions or glossary links: domain, entity, association, descriptor, extended reference; link to UML Notation and Conventions; explain the Handbook vs. diagrams vs. domain pages ("use the Handbook to look up an element, a domain Overview to learn why it is modeled that way").
6. Reference artifacts (each with a one-line description): Ed-Fi Unifying Data Model (UDM) Handbook v6.1 and v6.0, diagrams (Mermaid files on GitHub), bulk XML schemas, sample data (Grand Bend ISD), default descriptors.
7. What changed (3 bullets plus links): 5.2 to 6.0, 6.0 to 6.1, how to migrate.
8. Related standards and guidelines: Data Exchange Standards, Ed-Fi API Specification guidelines, XSD guidelines, how the standard is governed (one sentence), plus how it relates to the Ed-Fi ODS/API ("the Ed-Fi ODS/API implements the Ed-Fi API Specification built on the Data Standard").

### v6 Model Reference index (`model-reference/readme.md`)

Front matter: `description:` such as "Browse the 26 domains of the Ed-Fi Unifying Data Model (UDM) in Ed-Fi Data Standard v6.1, with a one-sentence scope for each domain and links to its pages." (155 characters). H1: "Ed-Fi Data Standard v6.1 Model Reference".

1. Opening (2 sentences). Names the Ed-Fi Data Standard v6.1 and says there are 26 domains, each documented on four kinds of pages (Overview, Model Diagrams, Entities/References/Descriptors, Readme).
2. How to use this section. How to pick a domain, the four page types in one sentence each, and a pointer to the Handbook for per-element detail.
3. Domain map. One table per group with columns Domain, What it covers (one sentence), Not covered here (go to), Status (for example "New in 6.0", "Early access (6.1)"). Proposed groups, to be confirmed by the Data Standard maintainers:
   - Organizations and calendars: Education Organization, School Calendar, Bell Schedule.
   - Students: Student Identification and Demographics, Enrollment, Student Cohort, Student Health, Student Attendance, Discipline.
   - Teaching and learning: Teaching and Learning, Student Academic Record, Graduation, Intervention, Alternative and Supplemental Services, Student Program Evaluation, Survey.
   - Assessment: Assessment, Assessment Registration.
   - Staff and educator pipeline: Staff, Credential, Educator Preparation Program, Path, Performance Evaluation, Recruiting and Staffing.
   - Finance and special education: Finance, Special Education Data Model (early access).
   Take each sentence from the domain readme's first sentence. Several need rewriting first: Credential ("provides background, rationale, and provides guidance"), Path (long, educator-only framing), and Special Education Data Model (starts with an admonition, not a definition).
4. Find a domain by question. A short topic-to-domain lookup table (for example "course grades and transcripts" to Student Academic Record; "class periods and bell times" to Bell Schedule; "teacher candidates" to Educator Preparation Program). This answers the 11 orientation misses above.
5. Reference artifacts. Handbook and diagram links per version with correct labels (2d2-14).
6. Changes and deprecations. What's New link plus the element-removal policy note (moved from the top), with a relative link.
7. Footer. Links to the Ed-Fi Unifying Data Model concepts pages and the Data Standard landing page.
