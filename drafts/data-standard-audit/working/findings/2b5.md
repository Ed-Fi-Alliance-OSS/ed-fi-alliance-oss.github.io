# Findings 2b5: Assessment, Student Program Evaluation, School Calendar, Bell Schedule (Data Standard v6)

## Scope

Agent 2b5. Every page under `dataStandard_versioned_docs/version-6/model-reference/` for four domains: `assessment-domain` (readme, overview, model-diagrams, entities, best-practices, 8 `.mmd`), `student-program-evaluation-domain` (5 pages, 2 `.mmd`), `school-calendar-domain` (5 pages, 2 `.mmd`), `bell-schedule-domain` (4 pages, 2 `.mmd`). 19 Markdown or MDX pages and 14 `.mmd` sources. Also the 32 questions in `questions.yaml` for these domains.

## Method

Read each source page in full and the `.mmd` entity lists. Compared against inventory-html.csv (words, `visible_words`, `empty_cell_ratio`, meta description), version-diff.csv, table-dupes.csv, terminology-hits.csv and retrieval-results.csv. Spot-checked built HTML in `build/` for assessment best-practices, assessment and bell diagrams, calendar overview and SPE best-practices (stray backticks in code blocks, image alt text, breadcrumb and version badge). Answerability judged from published page text only. Rubric scores are the lower of the learner and answer-engine views. Criteria that an element does not exercise (for example T1 on an overview with no large table) are scored 3 rather than n/a. Link validity of the legacy Confluence link was not checked (offline). Scores are not weighted here.

## Summary

- Consistency problems are concentrated in two places: the Bell Schedule entities page lists 10 items of which 2 are domain-owned (School and Session are "entities", AcademicWeek and GradingPeriod are "extended references"), and the SPE entities page omits the central StudentProgramEvaluation entity (2b5-30, 2b5-37).
- The School Calendar overview names a "CalendarEvent entity"; the model has a CalendarDate entity and a CalendarEvent descriptor, and best-practices uses CalendarDate. A learner searching "CalendarDate" hits only best-practices.
- Assessment best-practices JSON is corrupted in 5 of 6 code blocks (stray backticks, curly quotes, markdown links inside code), and the built HTML shows it; this is the page vendors copy from (2b5-18).
- Assessment overview carries its vendor-facing sample score report mapping in two images with filename alt text, and has a duplicated paragraph that stops mid-sentence (2b5-14, 2b5-15).
- Answerability: of 32 questions, 23 full, 6 partial, 3 none (q-bell-08 no page, q-cal-08 only in a diagram, q-spe-07 only in the v5 What's New); q-assess-08 is answered only in What's New too. Biggest vocabulary gaps: "A/B" (bell), "sub-scores" (assessment), "early childhood outcomes" (SPE), "instructional minutes" (bell).
- Cross-version duplication is acute: for these domains 25 of 32 questions list an older-version page in the top 3, and for q-assess-02 and q-assess-06 the v3 page is top-1; five v6 pages are 1.0 similar to v4 (and v3).
- Entities pages are 26 to 37 descriptor rows of which a minority belong to the domain (bell 1 of 31, calendar 5 of 37, assessment 23 of 39); empty-cell ratio 0.26 to 0.33.
- No domain page mentions a change history; whats-new-v60 has no link to the Assessment domain page (grep count 0).
- Terminology: 14 bare "Ed-Fi" uses across assessment, calendar and SPE pages; bell schedule has none.
- Diagram pages for bell and calendar have 28 visible words and no relationship text; assessment diagram page is the best of the four (prose per subdomain).

Severity counts: H=7, M=29, L=12 (total 48).
