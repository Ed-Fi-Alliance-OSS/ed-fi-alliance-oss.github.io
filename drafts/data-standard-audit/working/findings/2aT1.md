# Phase 2a-T: Terminology classification (v6 and UDM, non-accepted rows)

## Scope

- Input: `drafts/data-standard-audit/working/terminology-hits.csv`, rows where `set` is `v6` or `udm` and `rule` is not `accepted`.
- 127 rows: 92 from v6 (84 unlisted, 8 bare) and 35 from udm (30 unlisted, 4 bare, 1 avoid). No row carries `rule` = `verb`.
- Pages: 34 distinct files carry the 127 rows. Pages were also checked for their first "Ed-Fi" reference (see the first-reference section).
- Output: `drafts/data-standard-audit/working/findings/2aT1.csv` (one row per hit, columns as specified).
- Rulebook: `drafts/data-standard-audit/terminology-guidelines.md`, including the Audit Rulings section.

## Method

- The context column in the hits CSV was enough for most rows. Wrapped phrases, bare `Ed-Fi` cases, and ambiguous rows were checked in the source file.
- Line numbers in the CSV are not file line numbers. The hits script drops front matter, so the CSV line is 3 or 4 lower than the real line in most v6 files (for example, v6 `readme.md` CSV line 74 is file line 16). The findings CSV uses real file line numbers, verified by matching the context text in each file.
- Labels: `violation` = bare "Ed-Fi", avoid-list phrase, "Ed-Fi" plus an unlisted noun (for example, "Ed-Fi data model", "Ed-Fi domains", "Ed-Fi community" in lowercase), or a wrong official name. `acceptable` = accepted name split across a line break, or a proper name of an artifact, document, repo, page, or RFC used as link text or a title. `unsure` = not in the accepted list and the name may be official, or the fix depends on who is the referent.
- Judgment calls: "Ed-Fi" plus a domain name ("Ed-Fi Student Health domain") is labeled `violation` (low severity) because the rule is "Ed-Fi" plus an unlisted noun. "Ed-Fi" plus lowercase "data standard" is labeled `unsure` because the guideline allows the lowercase phrase alone but not with an "Ed-Fi" prefix. Writers may prefer to settle these as house style.
- First-reference check (rubric G1): for each page in scope, the first "Ed-Fi" occurrence was located in the source and tested against the accepted full forms.

## Summary

- 127 rows classified: 97 `violation` (76%), 21 `acceptable`, 9 `unsure`.
- Violations are spread across 31 pages. The main pattern is "Ed-Fi data model" (23 rows, 12 pages), followed by bare "Ed-Fi" + verb or preposition (19 rows, 9 pages) and "Ed-Fi" + unlisted noun in model-reference prose.
- The most common fix is "in the Ed-Fi Data Standard" for bare "Ed-Fi", and "in the Ed-Fi Unifying Data Model (UDM)" for "Ed-Fi data model". Both are safe to paste.
- Table headers ("Ed-Fi Entity", "Ed-Fi Element", "Ed-Fi Entities", "Ed-Fi Domains Needed") and "## Ed-Fi Prerequisites for Writing ... Domain Entities" headings repeat on 6 and 4 pages respectively. Fixing them in the domain templates would clear 11 rows.
- Six v6 pages use "Required attributes in Ed-Fi are hard constraints" (or a variant). This is one template sentence, so a single template edit would fix all six.
- 21 pages have a first "Ed-Fi" reference that is not a full accepted form (rubric G1). Six of these are "Ed-Fi data model" or "Ed-Fi model" in an overview or best-practices page's first paragraph. Several (for example, `udm/reporting-issues-and-making-suggestions.md`, `udm/getting-started/ed-fi-domains.md`) have the problem in the H1 or first sentence.
- Site-wide, lowercase "Ed-Fi community" appears 95 times in 57 files under `docs/` and `dataStandard_versioned_docs/`, and "Ed-Fi Unified Data Model" (wrong name) appears in 4 files. Neither is in the 127-row scope alone. Both are recorded once in the table below.
- The 9 `unsure` rows need a decision on governance and product names ("Ed-Fi Governance Groups", "Ed-Fi Jira Project", "Ed-Fi Resources API", "Ed-Fi Core data standard") and a single casing rule for "Ed-Fi data standard". These can go to the Sonnet pass.

## Notes for synthesis

- The hits CSV has two tooling issues that inflate the count and misplace lines. (1) Line numbers exclude front matter, so they are 3 or 4 below the real file line. (2) The regex misses accepted names split across a line break (for example, "Ed-Fi Unifying Data" + "Model (UDM)"), so some accepted rows were flagged. Fixing the regex to join wrapped lines would remove the wrap-only false positives; this scope has 6 of them (CSV rows for "Ed-Fi Unifying Data ... Model (UDM)", "Ed-Fi Alliance", "Ed-Fi UDM", and similar).
- Several "Ed-Fi" + unlisted-noun violations are artifact or domain names. A decision on whether "Ed-Fi <Domain> domain" is allowed would move about 3 violations to acceptable and clarify the domain template.
- A glossary decision for "Ed-Fi Governance", "Ed-Fi Resources API", and "Ed-Fi Core" would resolve the 9 unsure rows.
