# Findings 2c2: v5 delta audit (v5 pages that differ from v6)

AI-assisted draft: review before use.

## Scope

29 pages, lines 31-59 of `working/v5-delta-pages.txt` (paths relative to `dataStandard_versioned_docs/version-5/`):

- 10 `entities-references-and-descriptors.md` pages (school-calendar, staff, student-academic-record, student-attendance, student-cohort, student-health, student-identification-and-demographics, student-program-evaluation, survey, teaching-and-learning; student-health uses the file name `entities-references-descriptors.md`).
- 11 `model-diagrams.md` pages (no v6 file of the same name; v6 equivalent is `model-diagrams.mdx` with Mermaid).
- `staff-domain/overview.md`, `student-identification-and-demographics-domain/overview.md` and `best-practices.md`.
- v5 landing `readme.md` and `whats-new/` (`readme.md`, `api-changes-5.md`, `whats-new-v50.md`, `whats-new-v51.md`, `whats-new-v52.md`).

## Method

Read each v5 page against its v6 counterpart. Scripted row-level comparison of the three entity/reference/descriptor tables per page. Cross-checked `inventory.csv`, `version-diff.csv`, `table-dupes.csv`, `terminology-hits.csv`, `docusaurus.config.js` (version banners) and `docs/reference/0-roadmap/supported-versions.md` (DS 5.x active through the 2027-2028 school year). Rubric codes per `rubric.md`. Site-wide issues (no description, no version in title or H1, self-canonicals) are not repeated except where v5 adds something new.

## Summary

- **V-disambiguation is the main v5 problem.** 24 of 29 pages never say "v5" in body text (grep for v5/DS 5/v6 returns 0; student-health diagrams matches only an image URL). `docusaurus.config.js` sets `banner: 'none'` for v5, so the only signal is the version badge/dropdown. No v5 page says v6 exists or that v5 is supported through 2027-2028.
- **The v5 landing page (`readme.md`) makes a false currency claim.** It says "The most recent version and name for the Ed-Fi Data Standard is Ed-Fi Data Standard for Suite 3 v5.2.0", while v6.1 is current. It gives no guidance on choosing between v5 and v6.
- **The v5 What's New landing page is weak for version choice.** It lists v5.0-v5.2 only, omits `api-changes-5.md`, and has no breaking/non-breaking summary, no release dates, no migration guide and no pointer to v6. v6's equivalent has all but the migration content.
- **v5 descriptor tables are cleaner than v6's.** v5 pages list mostly domain-owned descriptors (for example school-calendar 6 rows vs 38 in v6; survey 4 vs 44), so the cross-domain duplication problem is far smaller in v5. v5 columns put "Entity" first, v6 puts "Name" first.
- **v5-only content errors found.** "Contract entity" (should be Contact), "SurveyResponce", two Program entries in the Student Program Evaluation tables, a copy-paste POST description in `api-changes-5.md`, "Visio format" in the landing page, and Student Health/Survey boilerplate that is wrong in both versions.
- **v5 diagrams are PNG images in Azure blob, not Mermaid.** 11 of 11 diagram pages have 1-4 images, 19-290 words, and no relationship text on 9 of 11. The diagrams carry the information; an answer engine sees only an alt string.
- **Most differences are legitimate model changes** (SEOA split into StudentDemographic/StudentDirectory/StudentIdentificationCode, new Staff entities, Student Program Evaluation moved Program out). None of the v5 overview pages say what v6 changed, and v6's overviews do say what changed from earlier versions.

## Notes for synthesis

- v5 has no migration guide; v6 does (`version-6/whats-new/migration-guide.md`). A "v4 to v5" guide is not needed if v4 is retired, but v5 pages should link the v6 migration guide for readers planning to move.
- v5 pages out of scope here (similarity at least 0.95 to v6) share the V1/V4 findings 2c2-02 and 2c2-29.
