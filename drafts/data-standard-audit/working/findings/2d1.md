## Summary

- There is no concept glossary. The only glossary (`core-concepts.md`, "Glossary of Terms") has three rows (Entity, Association, Attribute). "Descriptor", "extended reference", "domain", "reference", and "identity" are not defined anywhere in the UDM pages. Searching for "descriptor" in the UDM pages, `data-standards.md`, and `readme.md` returns zero hits. The only in-scope definition of a descriptor is in `technical-articles/descriptor-guidance.md` (outside the UDM folder, and the retrieval simulator does not rank it for "what is a descriptor").
- The Ed-Fi Domains page claims "17 base domains" while v6 has 26 domain folders. Nine domains are missing: Assessment Registration, Credential, Educator Preparation Program, Path, Performance Evaluation, Recruiting and Staffing, Special Education Data Model, Student Health, and Student Program Evaluation. A third count ("16 domains") appears in `docs/getting-started/sea-playbook/.../overview-of-ed-fi-data-domains/readme.md`. A learner who asks "how many domains" gets three answers (17, 16, 26).
- Version and support statements are stale. As of 2026-10-10, `data-standards.md` lists v4.0 and v3.x under "Active Versions", and `readme.md` labels v4 "(active)". `supported-versions.md` says v4.0.0 was active through 2025-2026 and v3.3.1 through 2024-2025. Neither page mentions that 6.1 exists. `data-standards.md` says "6.0 ... intended to support school years 2026-2027, and 2027-2028", but `supported-versions.md` says 6.x is "Active through 2029-2030".
- No page contrasts the Ed-Fi Data Standard, the Ed-Fi Unifying Data Model (UDM), the Ed-Fi ODS/API, and the Ed-Fi API Specification. The best sentence ("The data standard and the technology that implements the standard are two separate things") is in a Provider Playbook page, not in scope. The Ed-Fi Domains, Core Concepts, and landing pages also use "Data Standard" and "UDM" interchangeably.
- No page tells a reader how to read an "Entities, References, and Descriptors" page. The explanation of Usage Classification is a one-line link at the bottom of each table page, pointing outside scope.
- The UDM pages are not self-describing for retrieval. Meta descriptions are auto-derived from the first heading: `data-standards` is "Active Versions", `udm` is "Introduction", and v6 landing is "Documentation Home". The `udm` page's `title:` front matter ("Unifying Data Model") drops "Ed-Fi" from `<title>`.
- Strong existing material is buried or unlinked: `design-principles.md`, `uml-notation-and-conventions.md` (association labels, generalization), and `versioning-and-releases.md` (SemVer, breaking-change definition) are good concept sources, but the UDM readme links to none of the first two and gives no reading order.
- Several concept paragraphs are duplicated or mutually inconsistent across the UDM pages and the version-6 landing, with no single home (see Overlap table). `docs/reference/1-data-exchange/udm/udm-handbook.md` has a Handbook list that stops at v6.0 even though v6.1 is current.
- Findings: 4 H (high), 9 M (medium), 3 L (low) in the table below; one glossary page is the largest single fix.

## Learner journey narrative

A newcomer searching "what is the Ed-Fi Data Standard" gets, by `retrieval.py`, ODS/API binary-release pages, the v3, v5, and v6 landing pages, and `data-standards` (score about 2.8). The first Ed-Fi page they land on is likely a version landing page or an install page, not a definition.

If they land on `data-standards.md`, the first heading is "Active Versions", and the meta description is "Active Versions". They learn which versions exist (with stale support claims), then scroll to find that the standard is K-12, student-centric, extensible, and governed. The definition they wanted is split across `readme.md` ("widely adopted, CEDS-aligned"), the v6 landing ("The Ed-Fi UDM is the widely adopted ... data standard"), and Core Concepts.

They then meet undefined terms: UDM, normative and non-normative, domain, entity, association, descriptor, extended reference. The page says the UDM is "a logical model only and non-normative", but never says what that means for them.

"What is a descriptor" leads to metaed and API client pages. The in-scope Data Standard text mentions "Default Descriptors" only on the v6 landing page. `technical-articles/descriptor-guidance` has the definition ("data model elements that capture a controlled enumeration value", "code sets") but is not found by this query.

"What is the difference between the Data Standard and the ODS/API" returns an SEA playbook page and unrelated OneRoster pages. A newcomer who gets to the UDM follows `getting-started` to Core Concepts, which gives three glossary terms and a "17 base domains" list that is out of date (26 in v6). Next steps are unclear: Ed-Fi Domains links to the Model Reference, but the Model Reference domain pages open to a table of "Extended References" and "Descriptors" with no explanation.

Missing on-ramp pieces: a concept glossary (domain, entity, association, descriptor, extended reference, reference vs identity); a "how to read an entities, references, and descriptors page" section (and a lead-in on every such page); a Data Standard vs UDM vs ODS/API vs API Specification table; a domain map (26 domains, grouped, one line each, with links); and an explicit "start here" path from the UDM readme.

### Section 2: Model building blocks

| Term | Draft one-line definition | Source |
| --- | --- | --- |
| Domain | A view of the UDM that groups related entities, such as Assessment or Enrollment. | `ed-fi-domains.md` ("Domains serve to provide views of the Ed-Fi UDM") |
| Sub-domain | A named part of a domain, such as Gradebook within Student Academic Record. | `ed-fi-domains.md` "Sub Domains" |
| Entity | A classifier that describes a set of abstract or real objects sharing the same features, constraints, and semantics (for example, Student). | `core-concepts.md` glossary table |
| Attribute (element) | A property owned by an entity. | `core-concepts.md` glossary table |
| Association | A relationship between entities; an association that has its own attributes is named by joining the two entity names plus "Association". | `core-concepts.md`; `uml-notation-and-conventions.md` |
| Generalization (subclass) | A specialized entity that inherits attributes and associations from a broader one, for example School from EducationOrganization. | `uml-notation-and-conventions.md`; `design-principles.md` |
| Complex type / common (class used as an attribute type) | A reusable group of attributes, such as Address, used inside entities. | `design-principles.md` "Create Classes to Abstract Cohesive Groups of Attributes" |
| Identity (natural key) | The attribute or attributes that together define a unique record within an entity, shown in the "Identity" column of the Handbook. | `core-concepts.md` "Key Structure" |
| Reference | A way for one entity to point to another by that entity's identity (the association's "source" entity holds the reference). | `design-principles.md` "Consider the Direction of Associations"; needs SME |
| Extended reference | An entity shown in a domain's "Extended References" table that belongs to another domain but is referenced by this domain's entities. | `entities-references-and-descriptors.md` pages (observed, e.g. Graduation); needs SME to confirm and word |
| Descriptor | A model element that captures a controlled enumeration value; often called a "code set". | `technical-articles/descriptor-guidance.md` |
| Descriptor namespace | The URI that says who owns a descriptor value; only "ed-fi.org" namespace values are part of the Ed-Fi Data Standard. | `version-6/readme.md` "Default Descriptors" |
| Early access | Model content that can change outside the normal breaking-change cycle. | `versioning-and-releases.md` "Early Access Material" |
