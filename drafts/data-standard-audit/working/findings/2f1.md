# 2f1: Retrieval Simulation Judgment, Questions 1-126

## Scope

First half of `drafts/data-standard-audit/questions.yaml` (list positions 1-126,
`q-altsvc-01` through `q-cal-06`). Per-question rows are in
`working/findings/2f1.csv`.

## Method

- Inputs: `working/retrieval-results.csv` (BM25 over the built site),
  `working/corpus.jsonl` for page text, and the question `notes`.
- Verdict: _yes_ if a top-3 page answers for a newcomer (including a v6 page
  ranked 2-3 behind older copies); _partial_ if only older-version, adjacent,
  or thin pages answer; _no_ otherwise.
- Verdicts are judgment calls from keyword checks of page text, not full
  reads of every page. Directional only, as with the simulator itself.

## Summary

- 126 questions: 50 yes, 42 partial, 34 no (60% not fully answered).
- The expected page is in the top 3 for only 56 of 126 questions; for 39 it is
  not retrieved at all (no rank).
- An older Data Standard version (v3/v4/v5) is in the top 3 for 87 of 126
  questions, and is ranked first for 29. v4/v5 copies of domain pages are
  near-identical to v6 (same length in corpus), so BM25 ties are broken
  arbitrarily and the page title carries no version.
- Wrong-version is the largest miss cause (23). The v6 page is often outranked
  by v3/v4/v5 copies or by EPDM-era pages for domains that were renamed or
  newly added in v6 (Performance Evaluation, Path, Educator Preparation
  Program).
- Vocabulary mismatch (11) is next: learners say "school district", "teaching
  license", "bus route", "behavior code", "withdrawing"; the pages use
  LocalEducationAgency, Credential, StudentTransportation, Behavior
  descriptor, ExitWithdrawDate.
- Non-DS pages (12) outrank v6 pages mainly via certification test-scenario
  pages, SEA playbook instructional-time pages, Assessment Providers playbook
  pages, AMT view docs and ODS/API claim-set pages.
- Answer-absent (13): Recruiting and Staffing overview ("Coming Soon"), no
  best-practices page for Bell Schedule or Educator Preparation Program, no
  Intervention-vs-Program guidance, thin Graduation/Finance/Credential readmes.
- Table-only (10): answers exist only as a row in an entities table
  (StaffProgramAssociation, StudentTransportation, FeederSchoolAssociation,
  DisciplineIncidentExternalParticipant).

## Top recurring fix patterns

1. Version-disambiguate v6 pages (wrong-version, 23). Put "Ed-Fi Data Standard
   v6" in each v6 domain page's H1/title and opening sentence so v6 copies do
   not tie with near-identical v3/v4/v5 pages. Consider `noindex` or canonical
   to v6 for unchanged older-version domain pages.
2. Add a plain-language synonyms line to every domain overview (11 no + many
   partial): "In everyday terms: school district (LocalEducationAgency), teaching
   license (Credential), bus route (StudentTransportation)". Written in learner
   words, using entity names alongside.
3. Add a "Common questions" or "How do I record...?" prose section on each
   domain overview naming the entity and its association (table-only, 10).
   Move key entities out of tables into one-sentence prose.
4. Add a one-paragraph "X vs Y" disambiguation per domain overview where
   learners compare paired entities (Program vs StudentProgramAssociation,
   Assessment vs ObjectiveAssessment, session vs grading period, SSA vs
   SEOA, path phase vs milestone).
5. Fill documentation gaps (13): Recruiting and Staffing overview, Bell
   Schedule and Educator Preparation Program best-practices pages,
   Intervention vs Program guidance, assigned-vs-served suspension length.
6. Add domain-overview links from the non-DS pages that outrank the model
   reference (certification scenarios, SEA playbook, Assessment Providers
   playbook) so a learner lands on the v6 domain page next.
7. For v6-new domains, use renamed-domain wording on v6 pages ("formerly the
   Educator Preparation Data Model (EPDM)") and state "new in Data Standard
   v6.0" in each overview so what's-new queries and EPDM-era pages resolve to
   v6.
