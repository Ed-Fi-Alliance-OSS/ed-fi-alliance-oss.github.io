# Domain Dossier Harvesting Plan

## Goal

Ed-Fi Data Standard knowledge is scattered across this docs repo, the
certification docs, Jira, and Confluence RFCs, and a lot of institutional
history has been lost to staff turnover. This plan produces a reusable prompt
that generates a "dossier" per domain: current state, historical evolution and
design rationale, and known inconsistencies between sources — aimed at
onboarding new staff/contractors.

## Decisions

- **Domain scope**: all ~26 domain folders in
  `dataStandard_versioned_docs/version-6/model-reference/` (the 17 base UDM
  domains plus extension-driven ones like credential, path,
  educator-preparation-program, etc.), not just the 17 in
  `docs/reference/1-data-exchange/udm/getting-started/ed-fi-domains.md`.
- **History depth**: current (v6) state as the authoritative model
  description, plus narrative history pulled from Jira/Confluence/older
  version docs — not a full field-by-field version-to-version diff.
- **Execution target**: designed to be portable — usable in Rovo AI
  (Atlassian-hosted) or Claude Code + Rovo MCP. Local-file steps are tagged
  so Rovo AI (no repo access) knows to skip them.
- **Jira scope**: projects `DATASTD` and `MODL`, searched via JQL text match
  on domain name and key entity names (no reliable "domain" field exists on
  issues).
- **Confluence RFC scope**: descendants of
  <https://edfi.atlassian.net/wiki/spaces/rc/pages/712278041/Ed-Fi+Data+Standard+Request+for+Comments+RFC>,
  plus a general CQL fallback search in case a relevant RFC isn't nested
  under that page.
- **Certification alignment**: `docs/partners/2-certification/available-certifications/**`
  is not organized by domain, so it's searched by keyword (domain name + key
  entity names) rather than by folder lookup.
- **Discrepancies**: called out explicitly in a dedicated "known
  inconsistencies" section, written as an actionable punch list — not
  silently reconciled.
- **Audience**: internal onboarding for new staff/contractors — moderate
  depth, plain language, oriented toward "how did it get this way."
- **Output**: one new Confluence page per domain, created under
  <https://edfi.atlassian.net/wiki/spaces/DATASTDDEV/overview>, titled
  "Domain Dossier: {{DOMAIN_NAME}}". Draft is shown for review before
  publishing.
- **Run mode**: one domain per invocation (not a batch loop) — supply the
  domain name as a parameter each time, review, then move to the next. Pilot
  domain: Discipline (folder structure already confirmed).

## Source Map (confirmed by inspection)

| Source | Location |
| --- | --- |
| Current model docs (v6) | `dataStandard_versioned_docs/version-6/model-reference/<domain>-domain/` (readme.md, overview.md, entities-references-and-descriptors.md, best-practices.md, model-diagrams.mdx, `*.mmd`) |
| Prior versions | Same relative path under `version-5`, `version-4`, `version-3`; each version also has a `whats-new/` folder |
| General UDM conventions | `docs/reference/1-data-exchange/udm/` (design-principles.md, governance.md, udm-handbook.md, uml-notation-and-conventions.md) |
| Base domain list | `docs/reference/1-data-exchange/udm/getting-started/ed-fi-domains.md` (17 base domains; v6 model-reference has more) |
| Certification docs | `docs/partners/2-certification/available-certifications/**` (organized by certification type, e.g. `sis-v5`, `domain-api-v5`, `assessment-v5` — not by domain) |
| RFCs (published site) | `docs/reference/1-data-exchange/rfc/readme.md` — currently just a "Coming soon" placeholder; real RFC history lives in Confluence |
| RFCs (Confluence) | Descendants of space `rc`, page 712278041 |
| Design rationale (Jira) | Projects `DATASTD`, `MODL` |
